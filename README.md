# Stylizzer — AI Hairstyle Recommendation System

An explainable computer vision pipeline that analyses facial geometry and recommends personalised hairstyles based on anthropometric proportions, symmetry, and structural traits. Built around **interpretable features** and **transparent decision logic** — no black-box models for the core recommendation engine.

> **Live demo:** [stylizzer.vercel.app](https://stylizzer.vercel.app)

---

## How it works

```
Image → Quality Check → Landmark Detection → Hair Segmentation → Hair Classification
      → Geometric Feature Extraction → Trait Interpretation → Rule-Based Scoring
      → Ranked Recommendations → LLM Face Analysis → Generative Style Preview
```

Each step is fully inspectable. Features are normalised ratios derived from MediaPipe Face Mesh landmarks, calibrated against ~21,000 faces (UTKFace). Recommendations include per-feature contribution scores, explicit drawback analysis, and a face analysis summary driven by marginal trait influence.

---

## Key design decisions

**Geometry over deep learning** — all facial features are computed analytically from landmark coordinates, making the system auditable and easy to iterate on.

**Population-calibrated norms** — feature thresholds (p5/p25/p75/p95 percentiles) are derived from UTKFace split by gender, not hand-tuned. Recalculated after each feature set change.

**Hair segmentation for accurate facial thirds** — SegFormer segments the hair region and detects the hairline position for accurate upper facial third measurement. The hair mask is also passed to the skin tone analyser.

**Dual-head hair classifier** — a custom MobileNetV3-Small ONNX classifier trained on a coverage-stratified dataset detects hair texture (straight/wavy/curly/coily) and hairline shape (normal/receding/uneven). Coverage stratification eliminates the spurious correlation between short hair and receding hairline.

**Hair compatibility scoring** — hair type and hairline directly modify hairstyle scores via a configurable weight multiplier. Styles incompatible with the user's natural texture or hairline are penalised, not just ranked lower.

**Viewpoint-stable features** — features are selected and validated for stability across ±15° pitch/yaw variation. Unstable features (eye_height, nose_position, mid_lower_ratio) were identified through a self-consistency test across viewpoints and removed from the active feature set.

**Marginal influence face analysis** — face analysis is generated by computing the marginal impact of each trait on final scores: each trait is temporarily set to neutral and the score delta is measured. Only traits with meaningful impact are shown, eliminating explanations that contradict the final recommendation.

**Interaction-aware scoring** — rules encode trait combinations, not just individual signals. Hard constraints (e.g. receding hairline always caps certain fringe scores) take precedence over soft geometric signals.

**LLM-powered face analysis** — Groq (qwen3.8-27b) generates a personalised analysis based on marginal trait influence data.

**Fade level recommendation** — optimal fade gradient (low / mid / high / skin) derived from frontal face traits: jaw width, face length, cheekbone prominence and forehead height. Male-only feature.

**Skin tone analysis** — dominant skin undertone (warm / cool / neutral) extracted from the non-hair face region in Lab colour space (b* channel). Used to recommend compatible hair colour directions.

**Generative style preview** — ByteDance Seedream v4.5 generates a photorealistic hairstyle visualisation on the user's photo. Includes a Groq-powered salon transformation estimate (visits, months, difficulty).

**Explainability layer** — each recommendation includes positive contributions (why it fits), negative contributions (what works against it), and missing feature flags (what the style lacks that the analysis favours).

**Gender-aware pipeline** — InsightFace gender detection routes the analysis through separate trait classifiers, scoring rules, and hairstyle databases calibrated for male and female facial proportions.

**Structured error handling** — typed error codes (NO_FACE_DETECTED, FACE_TOO_SMALL, FACE_ROTATED, FACE_TILTED, POOR_ALIGNMENT) propagate from backend to frontend with user-facing guidance.

**Auth and premium gating** — Supabase auth (email/password) with Row Level Security. Analysis history persisted per user. Premium features (full recommendation set, style preview) gated behind a one-time Stripe purchase.

## Pipeline

### 1. Quality Assessment
Image validation before processing: magic-byte file type check, face size, yaw/pitch rotation bounds, brightness, and landmark alignment confidence. Typed blocking codes returned for each failure mode.

### 2. Landmark Detection
MediaPipe Face Mesh (478 landmarks). Normalised pixel coordinates used for all downstream geometry.

### 3. Hair Segmentation
SegFormer (jonathandinu/face-parsing) segments the hair region and estimates the hairline Y-coordinate for the facial thirds computation. Hair mask passed to hair classifier and skin tone analyser.

### 4. Hair Classification
Custom dual-head MobileNetV3-Small ONNX classifier:
- **Hair type**: straight / wavy / curly / coily
- **Hairline**: normal / uneven / receding

Hair coverage estimated from mask pixel ratio and used to approximate current hair length for the transformation estimator.

### 5. Geometric Feature Extraction
10 normalised ratios (after viewpoint stability testing):

| Feature | Description |
|---|---|
| `face_ratio` | Face height / width |
| `jaw_ratio` | Jaw width / face width |
| `jaw_to_height` | Jaw width / face height |
| `cheekbone_to_jaw` | Face width / jaw width — structural shape type |
| `eye_ratio` | Inter-eye distance / face width |
| `lip_ratio` | Mouth width / face width |
| `lower_face_ratio` | Mouth-to-chin / face height |
| `chin_prominence` | Chin projection from jaw midpoint / face height |
| `symmetry` | Multi-point lateral landmark asymmetry |
| `upper_third` | Hairline-to-brow / face height |
| `thirds_balance` | Max deviation from ideal 1:1:1 thirds ratio |

Removed from earlier versions after stability testing: `eye_height`, `nose_position`, `lower_third`, `mid_lower_ratio`.

### 6. Trait Interpretation
Features classified against population percentiles into semantic labels (e.g. jaw: narrow / normal / wide). Gender-specific thresholds. Face shape type (oval / triangle / square) derived from cheekbone-to-jaw ratio. Facial thirds dominance and balance computed from upper / middle third values.

### 7. Rule-Based Scoring
Weighted adjustments across hairstyle attribute dimensions with interaction rules and symmetry modulation. Hard constraints applied last.

Male dimensions: `volume_top`, `volume_sides`, `short_sides`, `longer_hair`, `fringe`, `clean_lines`, `soft_texture`, `textured_top`

Female adds: `layers`, `updo`, `curtain_fringe`

### 8. Hairstyle Matching
Scored against 12 male / 12 female hairstyles annotated with attribute weights and bilingual descriptions (PL/EN). Score normalised and clamped. Penalty applied for styles missing strongly-favoured features.

### 9. LLM Face Analysis
Groq (qwen3.8-27b) generates a personalised analysis from marginal trait influence data. Prompt instructs the model to give concrete styling direction, not describe features.

### 10. Fade Recommendation
Score-based rule engine maps frontal traits to a fade level (low / mid / high / skin) with a human-readable reason. Male-only.

### 11. Skin Tone Analysis
Lab b* channel of the skin-only face region (excluding hair mask) classifies undertone as warm / cool / neutral with a confidence score. Returns 3 recommended hair colour directions with hex swatches.

### 12. Generative Style Preview (Premium)
ByteDance Seedream v4.5 via fal.ai generates a photorealistic hairstyle edit from a crafted prompt per hairstyle. Groq estimates salon transformation time (visits / months / difficulty) from current hair length and target style.

## Localisation

Full PL / EN support throughout — UI strings, face analysis output, style descriptions, trait labels, legal pages, and error messages. Language toggle persisted to localStorage.

---

## Legal

GDPR-compliant for EU users. Facial photos processed as biometric data under Art. 9 RODO with explicit per-session consent. Photos not stored after analysis. Privacy Policy and Terms of Service available in PL and EN at `/privacy` and `/terms`.

---

## Feedback loop

Sessions log features, quality score, and top recommendations. Per-recommendation thumbs up/down votes stored separately. Collected data enables empirical weight calibration rather than manual tuning.

## Visual assets

Hairstyle reference images used in the UI are original photographs taken for this project or generated with AI tools for illustrative purposes.
